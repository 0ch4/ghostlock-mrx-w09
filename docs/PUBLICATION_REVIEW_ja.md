# 公開可否の裏取り（Publication review）

本リポジトリを **public にするか** の判断材料をまとめたものです。**法的助言ではありません**。
（最終判断は必要に応じて弁護士等にご確認ください。）

## 結論（要約）

* **脆弱性は完全に公開済み**（2026-07-07 disclosure、upstream 修正済み、**フルチェーン PoC も公開済み**）
  ＝ **NDay**。本リポジトリは**新しい脆弱性情報や汎用攻撃ツールを追加しません**。
* **法的リスクは低い**がゼロではない。**研究目的・自端末・対象1機種・免責明記**という枠組みを守れば
  public 化は妥当。
* **推奨**: public 化するなら README の免責・研究フレーミング・出典 NOTICE を維持したまま。
  より保守的なら private 継続、または**エクスプロイト本体を除いた writeup のみ**を public。

## 2. GitHub ポリシー

* GitHub Acceptable Use Policies（"Active Malware or Exploits"）は
  **dual-use なセキュリティ研究コンテンツを明示的に許可**し、脆弱性・マルウェア・エクスプロイトの
  **研究に関する投稿をサポート**するとしています。
* 一方で **「実際の攻撃で使われている PoC」は削除対象**になり得ます。
* 本件は**ローカル権限昇格（LPE）で特定機種限定・研究記録付き** → 通常は許容範囲。リスクは**低〜中**。
* 低減策: 研究目的・自端末限定・免責を明記し、**汎用化・自動化・ワンクリック化を避ける**。

## 3. 日本法の観点

| 論点 | 評価 |
|---|---|
| **刑法168条の2**（不正指令電磁的記録作成・提供罪） | 成立には「**正当な理由がないのに**」「**人の電子計算機**における実行の用に供する目的」＋**反意図性・不正性**が必要。**自端末での研究・PoC 公開はこれらを欠く**ため原則不該当。ただし「実行の用に供する目的」の解釈には幅があり、**説明可能性**が重要。 |
| **不正アクセス禁止法** | 規制対象は不正アクセス行為・識別符号の提供等。**エクスプロイトの公開自体は直接の処罰対象ではない**（悪用された場合は別問題）。 |
| **著作権法** | HKIP のソース引用は **GPLv2 に基づき帰属表示で適法**。`vmlinux` のシンボル名は著作物性が低い。技術的保護手段の回避規制（120条の2）は**著作物の保護技術**が対象で、ブート検証は該当しない。 |
| **外為法 / Wassenaar "intrusion software"** | 定義は監視・防御の回避等を指向し、**ローカル LPE の PoC は通常これに該当しない**。加えて**公開済み PoC の移植**であり新規性は低い。輸出管理の解釈は専門家確認が望ましい。 |

## 4. 倫理・ベンダー関係

* **自端末・研究目的**であり、CVE は公開・修正済み → **責任ある開示（Coordinated Disclosure）を損なわない**。
* Huawei への通知義務は既に CVE 化されているため不要。ただし **HKIP という端末固有防衛のバイパス**は
  Huawei にとって機微であり、公開は同社との関係に影響し得る点は留意。

## 6. 選択肢と推奨

| 選択肢 | 内容 | 向き |
|---|---|---|
| **A. public（エクスプロイト込み）** | CVE は公開済み・PoC も複数・移植＋HKIP 解析は研究価値が高い | 研究コミュニティへの還元。免責/NOTICE を維持 |
| **B. writeup のみ public** | 手法と HKIP 解析を公開し、エクスプロイトは非公開 | 最も保守的。再現性は下がる |
| **C. private 継続** | 現状維持 | 関係者共有のみ |

**推奨: A（免責・NOTICE を維持）**。より慎重にするなら B。
