## 重要な実測・教訓（新規）
1. **`root_cap_value` の park を 12→40 に増やすと CPU スピンで khungtaskd watchdog リセット**（`boot.reason=reboot,abnormal`、`Attempted to kill the idle task` ではない）。→ **12 に戻しスピンを 3e6→6e5 に短縮**。
2. **1ブート1復元ロックの順序バグ**：ロックを perf ゲート**より前**に取っていたため、hook ON 後の**早すぎる shell 発火1回でブートが復元不能**（`already handled`）。→ **ロックを perf ゲート通過後へ移動**（key=`btime`、overlay 判定は base 非依存）。
3. **app-domain `bugreportz` は perf を立てられない**（ソケット 0660 shell:log に接続不可）。⇒ tap下限は 1。
4. **バグレポートの種類ダイアログ**：Settings の「バグレポートを取得」→ **「完全レポート」→「報告」** の2段が追加である。a11y は両方クリックする。
5. **`--root-gms`（overlay + `ctl.restart zygote`）は PackageManager/ランチャーを劣化させる**。実測: **ランチャーが黒画面 → HOME activity 解決不能**。今回は **再起動で復旧**（`pm enable`＋`install-existing com.huawei.android.launcher`＋`pm disable-user --user 0 com.huawei.hwid` も実施）。`SAFETY_AND_RECOMMENDATION` の警告どおりで、**常用端末で繰り返すのは危険**。
6. 端末の `ghostlock_e` は **shield-free 既定**（`--root`/`--root-gms` = shield-free、`--root-old`/`--root-gms-old` が旧シールド）。`gms_setup.sh` は base を `$1` で受ける。

## 追加実測（異常リセットの正体・2026-09-26 後半）
- `boot.reason=reboot,abnormal`（= panic ではない）。`dropbox SYSTEM_LAST_KMSG`（一部化け）に:
  `InitWatchdog: init process is in d-state` / `hungtask: whitelist[...]-surfaceflinger / init / maple_zygote64 / system_server`
  / `watchdog pid-1703` / `sp805-wdt ... watchdog kick now ...`。
- ⇒ **full restore（overlay 3本 + `ctl.restart zygote`）を高負荷下で実行すると、init/重要プロセスが D-state に落ち、Huawei watchdog がリセット**する。**pid-0 panic ではない**。
- overlay の upper は **tmpfs 必須**（`/data`(f2fs) upper は **EINVAL**）。permissive が効いていても **AVC の stale deny で mount EACCES** になる場合があり、**AVC淘汰リトライ**を実装（今回 ACCESS は効いたが mount で失敗/リセット）。
- **結論**: root（シールド無し）は安定確立 ✅。しかし **real-GMS の per-boot overlay 方式は、本端末で高負荷時に watchdog リセットを招く**。これは `SAFETY_AND_RECOMMENDATION` の「常用では使うな」の実測的な裏付け。
- **推奨**: GMS は **microG + Aurora + ReVanced**（overlay不要・リセットなし）へ。overlay はテスト端末で単発のみ。
