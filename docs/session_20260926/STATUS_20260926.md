  / `watchdog pid-1703` / `sp805-wdt ... watchdog kick now ...`。
- ⇒ **full restore（overlay 3本 + `ctl.restart zygote`）を高負荷下で実行すると、init/重要プロセスが D-state に落ち、Huawei watchdog がリセット**する。**pid-0 panic ではない**。
- overlay の upper は **tmpfs 必須**（`/data`(f2fs) upper は **EINVAL**）。permissive が効いていても **AVC の stale deny で mount EACCES** になる場合があり、**AVC淘汰リトライ**を実装（今回 ACCESS は効いたが mount で失敗/リセット）。
- **結論**: root（シールド無し）は安定確立 ✅。しかし **real-GMS の per-boot overlay 方式は、本端末で高負荷時に watchdog リセットを招く**。これは `SAFETY_AND_RECOMMENDATION` の「常用では使うな」の実測的な裏付け。
- **推奨**: GMS は **microG + Aurora + ReVanced**（overlay不要・リセットなし）へ。overlay はテスト端末で単発のみ。

## 訂正（2026-09-26 終盤）: `/dev` の件は誤診
- 前段で「tmpfs が `/dev` を影にしている」と書いたが、**Android では `/dev` が tmpfs なのは正常**（原本 devtmpfs を tmpfs として mount）。実測で `ls /dev | wc -l` = **219**（正常）。誤診の原因は *フィルタ付き grep* で `mali0/graphics` しか表示しなかったこと。

## 追記: 「永続化」の徹底調査結論（2026-09-26）
- 公開情報＋corpus（`ghostlock_pocs/TASK_PERSISTENCE_20260926.md` 他）を網羅調査。
- **結論: native GMS を再起動をまたいで永続化するルートは存在しない**。
  - 起動時に書き込み可能領域から exec する rc アクション: 0（実機235で確認）。`load_filter_service`/`printservice` は **invalid keyword**（実機 init に無い）。
  - `dm-verity` 無効化は vbmeta が read-only で disable の時だけ。bootloader は **Kirin990 で unlock 不可**（公開コード終了、VCOM eFuse 無効化）。
  - `/preas`・`/cust`・`/vendor` 等はすべて EROFS ro。
  - `tzdatacheck`（唯一の /data 入力の boot exec）は固定長ヘッダ比較のみで、既知のメモリ破壊バグ無し。
  - PM の privileged フラグはスキャン時に再導出（`packages.xml` に永続値として書けない）。
- **唯一の reboot-persistent 効果**: GSF の `/data/app` 常駐（normal permission grant の保持）。
- ⇒ 最終形は **「毎ブート復元」**: 素材は /data に恒久、各ブートは overlay＋rescan のみ（約5秒）、起動はアプリ1操作 or DO完全自動。
